# Direct subscription OAuth execution for gateway integrations

Provider-owned OAuth credentials may back direct HTTP execution inside `execute` for integrations whose provider does not forbid it, one compiled adapter per provider. The gateway's `codex:oauth` reads `~/.codex/auth.json`, posts Responses-protocol SSE to the Codex backend with first-party client metadata, and refreshes an expired access token through the OpenAI token endpoint the same way the first-party CLI does, writing the rotated set back atomically. `copilot:oauth` exchanges the stored OAuth grant for a session token - reconciling through `/copilot_internal/user` on any auth-class rejection, which is how Business seats discover their `api.business.*` endpoint - then calls the Copilot chat endpoint directly. `devin:oauth` is registered for identity and listing only and refuses execution, because no documented first-party inference API exists for its local credential.

Anthropic and Google subscription OAuth execution is excluded by product decision: both providers' terms prohibit credential reuse outside their sanctioned clients, so `claude` and `gemini` subscriptions remain CLI-harness or monitoring-only. An OAuth adapter never fabricates capability - when execution is refused the error names the reason rather than degrading silently.

The credential boundary narrows but stays owned. The adapter reads and rewrites only its provider-owned file, only inside `execute`, and only after the credential is proven stale or rejected; monitoring collectors remain read-only. A refresh runs at most once per expiry (a serialized re-read under the adapter lock reuses a set another writer already landed), preserves every unrelated field and the 0600 mode, and touches nothing on disk when the exchange fails. Token material is marked sensitive, scrubbed from endpoint-controlled error text, and never logged.

This trades strict read-only monitoring evidence for execution speed and independence: direct HTTPS replaces CLI subprocess startup, its preflight probe, and its stdout protocol for the integrations that support it, at the cost of owning a small, provider-shaped client per OAuth adapter.
